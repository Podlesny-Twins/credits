# i18n — English version of credits.podlesnytwins.com

## What it is

`en/**` is generated by `build_en.py` from the *RU outputs* (`index.html`,
`track/**`, `faq/index.html`, `track-info.json`) using the dictionaries in
`i18n/en/`. Same DOM, CSS and JS as RU — only strings, `lang`, canonical /
hreflang / og:* and internal links change. Never hand-edit `en/**`.

## Usage

```bash
python3 build_who_mixed.py   # RU outputs, then runs build_en.py itself (--no-en to skip)
python3 build_tier.py        # /tier/ (RU only; EN pages link to it as "(Russian)")
python3 build_llms_full.py   # llms-full.txt from the rendered pages
python3 build_en.py          # standalone rerun after dictionary / FAQ edits
python3 build_en.py --strict # before a release: unmapped artists / untranslated stories are fatal
python3 build_en.py --check  # structural diff RU vs EN (tag sequences per page pair)
```

Order: `build_who_mixed.py` (→ `build_en.py`) → `build_tier.py` → `build_llms_full.py`.
A clean checkout builds in one pass: the RU side emits hreflang for exactly the
set of pages `build_en.py` produces (home, hub, FAQ, every live track page) without
looking at `en/**`.

Lenient mode (default) exists so the owner's add-track routine (`add_track.py`,
`sandbox/apply_edits.py`) never blocks on i18n:

- artist not in `artists.json` → Cyrillic name kept, listed as `artist-unmapped`;
- story with no translation in `notes.json` → omitted on the EN side (no note on the
  track page, no hub `<details>`, no `track-info.json` entry, no ⓘ button, JSON-LD
  description = role sentence only), listed as `story-untranslated`;
- any other Cyrillic UI string → fatal (a template changed; fix the dictionaries).

Exit 0 when only the first two are pending, with the line
`EN: N artists unmapped, M stories untranslated — see i18n/missing.txt`.
`--strict` makes them fatal; `--check` is unaffected (omitted stories are excluded
from the diff). `i18n/missing.txt` is the translator's to-do list.

Romanization on track pages: a Cyrillic release title gets a BGN/PCGN-style
transliteration once in `<title>`, description/og, the lead and as
`MusicRecording.alternateName` (`“Тысячи зим” (Tysyachi Zim)`); a Cyrillic artist
with an `artists.json._romanization` entry gets `Дора (Dora)` on its first lead
mention. Tiles, hub and home page stay untouched.

Local preview: `python3 -m http.server 4173 --directory <repo>` → http://localhost:4173/en/

## Dictionaries (`i18n/en/`, owned by the translation agent)

| file | content | lookup |
|---|---|---|
| `ui.json` | exact RU string → EN (text nodes, `alt`/`title`/`aria-label`/`placeholder`, meta/og content, FAQ answer paragraphs incl. inline HTML) | trimmed exact match; keys containing `<` are replaced on the raw HTML |
| `templates.json` | patterns of generated strings with `{artist} {title} {year} {role} {album} {n}` | regex built from the RU pattern; `{artist}` goes through `artists.json`, `{role}` through `ui.json`, `{title}`/`{album}` verbatim |
| `notes.json` | same keys as `/notes.json`, translated paragraphs | by key (track page, hub, JSON-LD description, `en/track-info.json`) |
| `artists.json` | RU display name → international name | text nodes, alts, JSON-LD `byArtist`, `ALBUMS`, breadcrumbs — never slugs/URLs |
| `llms.txt` | EN template with `{tracks}` / `{artists}` placeholders | → `en/llms.txt`, internal URLs re-pointed to `/en/` where the page exists |
| `ui.build-agent.json` | fallback for technical strings (JS literals, plural, role words) — lower priority than `ui.json` | same as `ui.json` |

Accepted shapes for `templates.json`: `{"ru": "en"}`, `{"name": {"ru":…, "en":…}}`,
`{"name": ["ru", "en"]}`. Keys beginning with `_` are ignored everywhere.

Resolution order for every string: exact `ui` → artist list → full template →
translated story paragraphs embedded in longer strings → templates as
substrings → word-boundary fragments (ui keys + artist names). Whatever still
contains Cyrillic goes to `i18n/missing.txt` (`file<TAB>context<TAB>string`),
except release titles, artist names not in `artists.json` (listed separately as
`artist-unmapped`), URLs, single letters (hub alphabet) and Cyrillic kept inside
quotes in translated stories.

## What works

- `/`, `/track/`, `/faq/`, 217 `/track/<slug>/` pages (redirect stubs skipped),
  `en/track-info.json` (home page fetches it), `en/llms.txt` when the template exists.
- Head: `lang="en"`, self-canonical, `og:url`, `og:locale=en_US`, hreflang ru/en/x-default,
  GA tag once, favicon + verification metas untouched.
- JSON-LD: same `@id`s for studio/persons/recordings; page node gets `/en/` url +
  `inLanguage: "en"`; `MusicRecording.name` never changed; descriptions / FAQ text translated.
- JS: `plt(n)` → `1 track / n tracks`; RU literals through the dictionaries;
  `fetch('/en/track-info.json')`; `ALBUMS[].artist` through `artists.json`.
- Hub: sections re-sorted and letter headings / jump links regenerated from EN names;
  `data-q` / `data-artist` get the EN name appended so search works in both languages.
- Links: internal links move under `/en/` when the counterpart exists; `/tier/`, `/edit/`
  stay RU with a " (Russian)" suffix on the link text; covers/favicon/fonts unchanged.

## Notes on the transform (things that were not a 1:1 string swap)

- Hub `/en/track/`: sections are re-sorted by EN artist name and the letter headings /
  jump links regenerated (Cyrillic initials merge into Latin ones, so EN has fewer
  letters). `data-q` / `data-artist` keep the RU keys and get the EN name appended.
- `{verb}` in track-page templates resolves through `roles.ROLE_VERB` first: the RU words
  "Кто свёл" are also the hub `<h1>` with a different EN rendering ("Who mixed it").
- Counter markup drifts (`<span class="num" data-n="works">217</span>` vs bare `217` vs
  `<span data-n=…>`): patterns match with or without the span and the EN output mirrors
  the RU span exactly, so the tag/attribute sequence stays identical. RU number spans
  the EN copy wrote without a span (`30 000` → `30,000`) are re-wrapped.
- `_contact_by_href` in `ui.json` overrides the link text of the contact links by href.
- Cyrillic deliberately kept inside quotes in translated stories / FAQ answers is not
  reported as missing; anything else Cyrillic outside titles and artist names is.
- The FAQ is hand-written and edited concurrently: when a paragraph no longer matches
  its key, its untranslated text-node pieces appear in `i18n/missing.txt` — the fix is
  to refresh that key in `ui.json`, never to edit `en/`.
