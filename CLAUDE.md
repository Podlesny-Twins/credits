# Podlesny Twins — Credits

Портфолио-дискография студии сведения и мастеринга Podlesny Twins (Павел и Антон Подлесные). Витрина работ: треки и альбомы с обложками и воспроизведением, фильтры по жанрам и наградам. Цель — за секунды доказать масштаб («они это свели») и подтолкнуть к контакту.

- **Live:** https://credits.podlesnytwins.com
- **Главный сайт:** https://podlesnytwins.com (пункт меню «Работы» ведёт сюда)
- **Repo:** https://github.com/lesnycode/credits

## Стек и деплой

- Один статический файл `index.html` — весь HTML/CSS/JS инлайн. Без сборки, без фреймворков (нет React/Vite/Next/TS/Tailwind).
- Деплой: GitHub Actions → GitHub Pages при пуше в `main` (workflow «Deploy static site to Pages»). Кастомный домен в `CNAME`.
- `gh run watch <id>` — следить за деплоем.

## Архитектура index.html

- `.pf` — корневой контейнер, тёмная сцена (`#1a1a19`).
- `.pfnav` — шапка: лого `.pfbrand` (→ главный сайт) слева, `.navlinks` справа: `.pflink.pfworks` («Наши работы», активный красный, текущий раздел) + `.pflink` «Курс» (→ podlesnytwins.com), между ними hairline-разделитель (`border-left` на втором `.pflink`), оба uppercase в тон фильтрам. Стрелка `.ar` у «Курс» скрыта внутри `.navlinks`. **Важно:** класс `.pfmenu` уже занят дропдауном в футере (`#pfmenu`) — для шапки использовать `.navlinks`, не переиспользовать `.pfmenu`.
- `.hero` — тонкая полоса-осциллограф (~18px десктоп / 16px мобила), `<canvas id="waves">`, **без баннера-заголовка**. Фон прозрачный, canvas чистится `clearRect` (тёмной заливки-«блока» нет) — видна только линия (красная + приглушённая серая) по центру (`y=H/2`). Амплитуда масштабируется к высоте (`hs=H/100`), есть idle-baseline (линия «живёт» и реагирует на курсор без проигрывания, сильнее при play), уважает `prefers-reduced-motion`. Заголовок `<h1>Podlesny Twins Credits</h1>` сохранён как `.sr-only` (визуально скрыт, для SEO), сам hero `aria-hidden`.
- `.filters` — типографская строка фильтров (без pill-кнопок). `data-f` = жанр (ALL/HIPHOP/POP/INDIE/ROCK) или награда (GRAM/TOP1). Счётчики `.fc` считаются JS из `data-g`/`data-aw`.
- `.grid` / `.tile` — карточки треков и альбомов. Одиночный трек: `data-g` (жанр), `data-id` (Spotify ID), `onclick="play(this)"`. Альбом: `.tile.album`, `onclick="openAlbum(N)"`, данные в массиве `ALBUMS`.
- Порядок тайлов: сгруппированы по основному артисту (треки одного артиста идут подряд), коллабы — по первому артисту в строке («Dima Bilan» и «Дима Билан» = один). Сверху закреплены группы: PIZZA → Билан → MACAN&NAVAI → T-Fest → Андрей Катиков; далее остальные по первому появлению. Дублей тайлов быть не должно (дедуп по `data-id` / по альбому).
- Награды: атрибут `data-aw` на тайле (`GRAM`/`TOP1`) — управляет только фильтрацией (визуальных бейджей на карточках нет, убраны).
- Плеер: нижняя панель `#player`, использует **Spotify iFrame API** (`onSpotifyIframeApiReady` → `spotifyCtrl`). `play(el)` делает `loadUri`+`play` внутри клика; повторный клик по активной карточке = `togglePlay`. Иконка ▶ → пауза (две полоски `.pb`) по событию `playback_update`.
- Мобильный автоплей (iOS/Safari часто блокирует): флаг `wantPlay` + класс `.tile.retap` — пульс play-кнопки (`@keyframes retap`), подсказка «тапни ещё раз». В `playback_update`: если `wantPlay && isPaused` → `resume()` + `.retap`; при реальном старте `.retap` снимается. Логика чувствительная — менялась братом несколько раз, текущая версия «retap + wantPlay».
- Модалка альбома `#amodal`: `role="dialog"`, закрытие по Esc и клику по фону.

## Бренд / правила дизайна

- Регистр: **brand** (design IS the product). Характер: профи, мощь, премиальность.
- Анти-референс: дженерик-лендинг «от нейросети» (шаблонные pill-кнопки, дефолтные шрифты, одинаковые карточки-сетки, разноцветный glow). Если не отличить от тысячи AI-лендингов — провал.
- Один акцент: брендовый красный `#cf2c04` (идентичен главному сайту). Всё прочее — оттенки тёмного.
- Заголовочный шрифт `SaarSP` (заглавные, тяжёлый рубленый) — с Tilda CDN, тот же, что на главном сайте. Текст — Work Sans.
- WCAG AA: контраст ≥4.5:1, видимый фокус, тач-таргеты ≥44px.

## Контент / конвенции

- Обложки: `https://i.scdn.co/image/ab67616d0000b273<hash>` (640px). Хеш брать из Spotify oEmbed (`/oembed?url=...` → `thumbnail_url`, заменить размер на `ab67616d0000b273`).

- Множественное число треков — JS-хелпер `plt(n)` (трек/трека/треков). На бейджах альбомов писать полным словом, не «тр.».
- **Иноагенты:** карточки Morgenshtern помечены `<sup class="ia">*</sup>`, в футере сноска `.iadisc`. При добавлении контента иноагентов — тот же маркер + сноска.

## Песочница — правки владельцем

Приватная страница-артефакт, с которой Павел правит сайт с телефона, не открывая
репозиторий: **https://claude.ai/code/artifact/a4be077f-953d-430c-90f2-5cd40a1902b3**

Три входа, все ведут в один и тот же артефакт:

- **credits.podlesnytwins.com/edit** — короткий постоянный адрес (`edit/index.html`,
  редирект; `noindex` + `Disallow` в `robots.txt`).
- **github.com/lesnycode/sandbox** — приватный репозиторий-дверь: README со ссылкой и
  инструкцией. Виден только под учёткой владельца, посторонним 404.
- Ярлык на домашнем экране телефона — основной способ в быту.

При переезде песочницы на другую учётную запись ссылку меняют **в двух местах**:
`edit/index.html` (строка `var SANDBOX`) и README репозитория `lesnycode/sandbox`.

Она ничего не меняет на сайте сама и не имеет доступа к репозиторию — только копит
список правок внутри себя (блок `<script id="state">`) и пересохраняется как новая
версия себя. Правится: роль, жанр, награда, описание трека, «спрятать с сайта»,
**порядок плиток на сетке**; плюс очередь новых ссылок на Spotify.

Описание — не пустой textarea, а три вопроса (кастуются из небольшого банка формулировок
по хешу ключа работы, так что у соседних работ они звучат чуть по-разному, а у одной и той
же — стабильны между открытиями). Кнопка **«Интервью»** в каталоге — быстрый проход подряд
по всем 217 позициям (сначала без текста), карточка на весь экран с прогрессом,
«Пропустить» / «Дальше». Позиция интервью хранится в `state.interview` — переживает
принудительную перезагрузку после каждой публикации (см. ниже).

**Двойная запись ответов.** Каждая публикация перезагружает страницу, и если публикация
падает (сеть, 404 на перезагрузке, закрытая вкладка), всё, что жило только в публикуемом
документе, теряется молча — так у владельца пропал прогресс за несколько артистов.
Поэтому текст ответа пишется ещё и в `localStorage` (ключ `credits-sandbox-draft-v1`),
при загрузке подмешивается обратно в `state.edits` и очищается только после успешной
публикации. Ошибку публикации показывает плашка в самой странице (`alert()` во фрейме
артефакта не показывается) плюс автоповтор через 1.2 с.

Файлы в `sandbox/`: `catalog.py` (чтение каталога — слаги и разбор тайлов
импортируются из `build_who_mixed.py`, чтобы ключи не разошлись), `build_sandbox.py`
(сборка страницы), `apply_edits.py` (перенос правок в данные), `template.html` /
`app.css` / `app.js` (сама страница).

### Порядок применения

Публикация страницы будит открытую сессию Claude Code. Дальше:

1. Прочитать артефакт, взять `state` из `<script id="state">`.
2. **Есть `ready`** — забирать. **Нет** — правка ещё в работе, не трогать.
3. Сохранить состояние в файл и применить:
   `python3 sandbox/apply_edits.py <state.json>` — печатает применённое и,
   отдельным блоком, **ненайденное**. Непустой блок «НЕ ПРИМЕНЕНО» разбирать
   обязательно: это молчаливо потерянные правки.
4. Очередь новых ссылок применять скиллом `credits-add-track` (команды скрипт печатает).
5. `python3 build_who_mixed.py`, проверить сайт, запушить как обычно.
   **Обложки нового трека:** коммит от `fetch-covers` сделан ботом, а действия бота
   не запускают другие workflow — деплой для него не стартует сам. После добавления
   трека: `gh workflow run "Deploy static site to Pages" --ref main`, иначе обложка
   отдаёт 404 при живом тайле.
6. **Пересобрать песочницу из свежих данных:** `python3 sandbox/build_sandbox.py`
   и переопубликовать по тому же URL — иначе она покажет уже выкаченное как неотданное.

Если сессия была закрыта и уведомление никто не увидел, владелец пишет обычным
сообщением — порядок выше не зависит от предыстории разговора.

### Что делает `apply_edits.py`

| Поле | Куда уезжает |
|---|---|
| роль | `roles.json` по Spotify ID (у альбома — всем его трекам) |
| описание | `notes.json` по слагу, который считает сам сборщик |
| жанр, награда | атрибуты `data-g` / `data-aw` на тайле в `index.html` |
| спрятать | тайл целиком вырезается в `hidden.json` (с якорем-соседом), страницы `/track/<slug>/` удаляются |
| порядок | тайл вырезается и вставляется после тайла-соседа в `index.html` |

Перемещение хранится **относительно соседа** (`{"key": …, "after": …}`, пустой `after` =
в начало сетки), а не абсолютным номером: номер молча означал бы другое место после
любой другой правки. Топ-30 плиток — отобранные вручную миксы, поэтому порядок и
доверен владельцу.

Скрытая работа остаётся в каталоге песочницы и возвращается оттуда же — карта целей
строится по всем работам, а не по тем, что попали в сборку.

**`openAlbum(N)` — это индекс в массиве `ALBUMS`.** Поэтому скрытие альбома
пересобирает и массив, и нумерацию в тайлах разом (`sync_albums`): иначе альбомы
после скрытого молча начнут открывать чужой контент.
